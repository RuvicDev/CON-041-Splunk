¿Qué es y para qué sirve?

El conector Splunk permite que el agente de Ruvic consulte eventos y logs indexados en Splunk — ejecutar búsquedas SPL, explorar qué índices existen, y revisar el resultado de una búsqueda anterior.

Una vez configurado, puedes pedirle al agente cosas como:

  • "¿Qué eventos de error hubo en las últimas 4 horas?"
  • "¿Qué índices hay disponibles?"
  • "Revisa el resultado de esa búsqueda que quedó corriendo."

Operaciones soportadas:

OperaciónQué hace
siem.execute_spl_searchEjecuta una búsqueda SPL y trae sus resultados
siem.list_indexesLista los índices disponibles
siem.get_job_resultsConsulta los resultados de un job de búsqueda existente
Protección de seguridad incorporada Por defecto, este conector bloquea comandos SPL que escriben o ejecutan algo fuera de la propia búsqueda (delete, outputlookup, collect, script, sendemail, etc.) — solo consulta datos.

Prerrequisitos

  • Un servidor Splunk (Enterprise o Cloud) accesible por red desde donde corre Ruvic, con el puerto de administración (8089 por defecto) abierto.
  • Un usuario o token dedicado a esta integración — nunca una cuenta administrativa.
  • Para pruebas: puedes levantar un Splunk local con Docker en vez de conectarte a un ambiente productivo (ver sección de Verificación).

Configuración en el fabricante

Camino A — Token de autenticación (recomendado)

  1. Pide al administrador de Splunk que cree un token. En Splunk Web: Settings → Tokens → New Token, asociado a un usuario de servicio (no admin) con el rol adecuado.
  2. Confirma la URL del puerto de administración. Normalmente es la misma URL de Splunk Web pero con el puerto 8089 en vez del 8000.

Camino B — Usuario y contraseña

  1. Pide al administrador un usuario de servicio dedicado. Con rol "user" y capacidad de búsqueda ("search") sobre los índices necesarios.

Prueba desde línea de comandos (opcional pero recomendado):

curl -k -u usuario:contraseña \
  "https://TU_SERVIDOR:8089/services/data/indexes?output_mode=json&count=1"

Una respuesta con datos de índices confirma que las credenciales funcionan.

Permisos requeridos

PermisoPara qué lo usa el conector
Capacidad "search" sobre los índices relevantesNecesario para las 3 operaciones

No otorgues el rol "admin" — el conector solo necesita poder buscar, no administrar la plataforma.

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta Splunk y pulsa Configurar. Elige el modo (token o usuario/contraseña) según lo que tengas.

Completa la URL del puerto de administración (incluyendo :8089) y las credenciales del modo elegido.

Guarda y pulsa Probar conexión.

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: "Conexión exitosa a [URL] (modo: ...)".

  2. Prueba mínima con el agente.

    Pide algo de solo lectura primero:

    "¿Qué índices hay disponibles?"

Para probar sin depender de un Splunk productivo, puedes levantar uno local con Docker:

docker run -d --name splunk-test -p 8089:8089 -p 8000:8000 \
  -e SPLUNK_START_ARGS='--accept-license' \
  -e SPLUNK_PASSWORD='ContraseñaSegura123!' \
  splunk/splunk:latest

Espera 1-2 minutos a que Splunk termine de iniciar antes de probar la conexión.

Solución de problemas

Mensaje / síntomaCausa probable y solución
"Autenticación/permisos insuficientes" (HTTP 401/403)Token/usuario/contraseña incorrectos, o la cuenta no tiene capacidad "search" sobre el índice consultado.
"No se pudo conectar..." (timeout/red)Verifica que el puerto 8089 (no el 8000 de Splunk Web) esté abierto y accesible desde donde corre Ruvic.
Error de certificado TLSMuchas instalaciones de Splunk usan certificados autofirmados en el puerto de administración — considera desactivar "Verificar certificado SSL" solo si confías en la red, o instala un certificado válido.
"is_done": false en execute_spl_searchLa búsqueda no terminó dentro del tiempo de espera configurado — no es un error; usa get_job_results con el sid retornado para consultarla más tarde, o aumenta "Espera máxima por un job".

Preguntas frecuentes y notas de seguridad

¿El agente puede eliminar o modificar eventos?

No, por defecto. El conector bloquea automáticamente los comandos SPL de escritura/ejecución salvo que se active esa opción explícitamente.

¿Por qué se recomienda usar token en vez de usuario/contraseña?

Un token se puede revocar individualmente sin cambiar la contraseña de una cuenta compartida, y no expone la contraseña real del usuario de servicio en la configuración del conector.

¿Dónde queda guardada la credencial?

Como secreto en el almacén de credenciales de la plataforma. La interfaz nunca vuelve a mostrarla.

Buenas prácticas Usa un token o usuario dedicado, nunca una cuenta admin; deja el bloqueo de comandos de escritura activado salvo necesidad real; y siempre acota tus búsquedas con earliest_time para no escanear todo el histórico.
